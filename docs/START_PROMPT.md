# Стартовый промпт для нового чата

Работаем над проектом `E:\WORK\pet\bang-online` — приватной браузерной онлайн-версией BANG! для игры с друзьями с компьютера, телефона и планшета.

Сначала прочитай `AGENTS.md`, `README.md`, `docs/PROJECT_BRIEF.md` и `docs/SETUP_STATUS.md`, затем изучи текущие файлы и проверь состояние проекта. Это подготовленный каркас, а не готовая игра. Не считай комнаты, игровую механику и сохранение партий реализованными без проверки кода.

Согласованные решения:

- Первая версия — только классическая BANG! на **4–7 игроков**, в итоге со всеми базовыми картами и персонажами.
- Dodge City, режимы на троих/восьмерых, Redis, боты, публичный подбор игроков, встроенный голосовой чат и нативные приложения пока не делаем.
- Стек: TypeScript, React/Vite, Node.js 24, Fastify, Socket.IO, PostgreSQL; npm workspaces.
- Игровой движок находится в `packages/game-core` и не зависит от интерфейса, сети или базы. Публичные контракты — в `packages/contracts`.
- Сервер проверяет действия и хранит скрытые данные. Клиент получает только разрешённое конкретному игроку представление.
- Надёжное возвращение после обновления страницы и обрыва связи важнее декоративных эффектов.

Продолжи разработку с первым ограниченным, проверяемым этапом: **приватное лобби с гостевыми местами и возвращением на своё место после обновления страницы или переподключения**.

Нужно создать комнату, приглашать по ссылке, входить по имени, занимать место и менять готовность. Ожидать в комнате можно и меньшим составом; классическая партия требует 4–7 готовых игроков. Владение местом должно подтверждаться безопасным секретом сессии, а не именем или одним публичным кодом комнаты. Определи и проверь поведение при повторном входе, нескольких вкладках, заполненной комнате и неверном секрете. Сохрани необходимые для этого этапа данные в PostgreSQL через явные миграции. Продумай безопасный способ переноса сессии между устройствами позже, но не расширяй текущий этап без необходимости.

Сначала проверь каркас и выбери небольшой план реализации. Затем самостоятельно доведи этот этап до работающего состояния, добавь содержательные тесты и обнови документацию. Не начинай одновременно реализовывать всю игру или будущие дополнения. Не добавляй зависимости и инфраструктуру без конкретной необходимости.

Проверяй изменённое поведение, затем запускай `npm run check`. Если Docker/PostgreSQL недоступен, точно укажи, какие проверки не состоялись; не выдавай проверку живого процесса за проверку базы. Не удаляй существующие данные и не сбрасывай Docker volumes без прямого разрешения.

Общайся со мной по-русски, внутреннюю документацию пиши по-английски. Продолжай обычные безопасные правки и проверки без вопросов «продолжать ли». В финале кратко укажи, что работает, как запустить и проверить, какие ограничения остались и какой следующий небольшой этап логичен.
